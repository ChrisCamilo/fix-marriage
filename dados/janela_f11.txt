# O ESTADO
#
#   frame 11, NAL em 147689, 2832 bytes
#   para no macrobloco 15, fileira 0 -- 0,2% do payload
#   8160 - 15 = 8145 macroblocos de ocultacao, que e exatamente o numero ja
#   medido antes por outro caminho
#   imagem: DOIS valores, 15 e 43
#
# A fileira 0 e TARJA, entao ele quebra dentro da tarja de cima, no 16o
# macrobloco. Nao e "o quadro nao decodifica": e "o quadro nao passa da tarja".
#
# O ALVO, medido nos vizinhos do fade:
#
#   frame  8 -> [16, 32]     frame 10 -> [16, 36]
#   frame  9 -> [16, 38]     frame 12 -> [16, 41]
#   frame 11 -> [15, 43]  <- deveria ser [16, 43]
#
# Todo quadro do fade tem exatamente DOIS valores: tarja 16 mais o campo. O
# campo 43 ja esta certo -- e o que a rampa preve. Falta so a tarja.
#
# ============================================================================
# A TARJA 15 NAO E UM DEFEITO SEPARADO -- NAO PROCURAR BIT PARA ELA
#
# Medido no GOP 0 inteiro:
#
#   frame   tarja topo      tarja base      campo
#   0..10   16,000/0,000    16,000/0,000    16 a 38   <- todos certos
#   11      15,000/0,000    15,000/0,000    43        <- o unico anomalo
#   12      16,000/0,000    16,000/0,000    41
#
# Nao ha erro nos frames 0 a 10. E a rampa fecha em ordem de exibicao:
#   16 18 21 23 25 27 29 32 34 36 38 41 43
# O frame 11 e o ULTIMO quadro do fade, e o campo 43 dele ja esta certo.
#
# O QUE FECHA A QUESTAO: os 15 macroblocos que o frame 11 REALMENTE decodifica
# tambem saem 15. Medido na faixa x=0..239, y=0..15, que e exatamente MB 0 a 14:
#
#   frame 11, MB 0-14 (decodificados) ... [15]
#   frame 11, MB 15+  (ocultacao) ....... [15]
#   frame  9, mesma faixa ............... [16]
#
# Quando o erro bate no macrobloco 15 o ffmpeg descarta o quadro inteiro e
# oculta tudo, inclusive o que ja tinha decodificado. A tarja 15 e a saida da
# ocultacao: 1,25 * 16 - 5 = 15, a predicao ponderada do fade aplicada a tarja
# 16 do frame 9. A tarja ocupa 260 linhas (0-129 e 950-1079) e as 260 estao em
# 15, a mesma geometria que nos quadros bons da 16.
#
# CONSEQUENCIA PRATICA: quando o frame 11 decodificar de verdade, a tarja sai 16
# sozinha, como em todos os vizinhos. Nao ha bit de tarja para procurar.
#
# E os 5 candidatos da JANELA A ficam DESQUALIFICADOS como reparo: eles mexem
# nos pesos, ou seja, consertam o que a OCULTACAO produz, nao o quadro. Por isso
# entregam tarja 16 e estragam o campo. Servem de diagnostico, nao de conserto.
#
# O alvo e um so: fazer o frame 11 passar do macrobloco 15. Tarja e campo vem
# juntos.
#
# ============================================================================
# SAO DUAS JANELAS, E CADA UMA RESOLVE METADE
#
# JANELA A -- bytes 8 a 11 (absoluto 147697-147700): os pesos no cabecalho
#
#   5 bits de 1 flip entregam tarja 16,000/0,000 em CIMA e EMBAIXO:
#
#     byte  8 b5   tarjas 16   campo 38   <- campo do frame 9: copia pura
#     byte  8 b6   tarjas 16   campo 38   <- idem
#     byte 10 b4   tarjas 16   campo 44
#     byte 10 b5   tarjas 16   campo 45
#     byte 11 b5   tarjas 16   campo 44
#
#   Nenhum da 43. Isso CONFIRMA por medida o que o registro ja dizia por
#   aritmetica: "a tarja em 16 custa campo 44; a rampa custa campo 43; os dois
#   nao coexistem com peso inteiro".
#
# JANELA B -- bytes 18 a 30 (absoluto 147707-147719): os primeiros macroblocos
#
#   14 bits de 1 flip fazem o quadro decodificar INTEIRO, macrobloco 8160 sem
#   erro nenhum. TODOS mantem campo 43 e tarja 15:
#
#     byte 18 b0, byte 20 b7, byte 22 b3   -> imagem byte a byte IGUAL a base
#     os outros 11                          -> tarja de cima com ruido
#
#   Os tres limpos sao o ponto de partida do encadeamento: o quadro passa a
#   completar sem erro, entregando o mesmo que a ocultacao entregava.
#
# COMO A JANELA B FOI LOCALIZADA -- tres medidas independentes concordam
#
#   1. `corta`: cortar em 22 bytes chega ao macrobloco 429, fileira 3. Com MENOS
#      dados ele vai MAIS longe -- os bytes seguintes derrubam o decodificador.
#      Do byte 32 em diante, travado no 15 para sempre.
#   2. os 14 bits que completam o quadro estao todos entre os bytes 18 e 30.
#   3. os 5 bits que dao tarja 16 estao todos nos bytes 8 a 11, fora dela.
#
# ============================================================================
# O DIAGNOSTICO
#
# Num quadro sao a tarja e INTRA e nem passa pela tabela de pesos. No frame 11
# tudo virou skip ponderado, tarja inclusive, e por isso ela sai 1,25*16-5 = 15.
# Mexer nos pesos (janela A) conserta a tarja e estraga o campo, porque o mesmo
# peso faz os dois trabalhos. O conserto tem que fazer os primeiros 960
# macroblocos voltarem a ser intra -- e isso mora na janela B.
#
# Por isso e problema de 2 bits ou mais, e por isso o encadeamento e o caminho:
# fixar um bit da janela B que faca o quadro completar, e varrer de novo
# exigindo tarja 16 com campo 43.
#
# formato: offset bit   (candidatos da janela B que completam o quadro limpo)
147707 0
147709 7
147711 3
